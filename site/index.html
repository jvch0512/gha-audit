gha-audit

Static audit of GitHub Actions workflows. Ruby, standard library only. Report on the synthetic workflows in examples/.

10 findings.

SeverityRuleWhereWhat and how to fix
criticalGHA001pr-bot.yml > buildpull_request_target checks out untrusted pull request code
Fix: Do not check out the PR head in a pull_request_target workflow, or split the workflow: build untrusted code under pull_request without secrets, and run privileged steps in a separate workflow_run job.
highGHA002pr-bot.yml > build${{ github.event.pull_request.title }} is attacker-controlled and expanded into a shell script
Fix: Pass the value through an environment variable and reference it as a shell variable, never inline ${{ }} inside run.
highGHA005pr-bot.yml > buildRemote script piped into a shell
Fix: Download, verify a checksum or signature, then run.
highGHA007release.yml > publishInsecure commands re-enabled
Fix: Remove ACTIONS_ALLOW_UNSECURE_COMMANDS and use environment files.
mediumGHA008call.yml > deploySecrets passed to a reusable workflow with inherit
Fix: Pass only the secrets the called workflow needs.
mediumGHA003call.yml > deployreusable workflow my-org/shared/.github/workflows/deploy.yml@main is not pinned to a commit SHA
Fix: Pin to the full 40-character commit SHA and keep the tag in a comment, so a moved tag cannot change what runs.
mediumGHA004pr-bot.ymlNo permissions block: the token gets the repository default, often read-write
Fix: Set permissions: contents: read at the top and grant more per job only where needed.
